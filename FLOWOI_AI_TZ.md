# Flowoi — ТЗ AI (полное)

> Документ описывает **только AI-часть** продукта Flowoi. Базовые принципы продукта, модель данных и термины — в `FLOWOI_TZ_dev.md`; здесь — всё про AI.
>
> Инфраструктура AI уже частично есть: **отдельное репо**, деплой на **Render**, **ключи GPT (OpenAI)**. Детали — в разделе 8.
>
> Нейминг: бренд во фронте — Flowoi; код/БД основного сервиса — `ozonpro` (не переименовывать).

## 0. Что такое AI в Flowoi

AI — это **аналитический мозг поверх всех данных Ozon** + **диалоговый чат** к нему. Не болталка и не анализатор отзывов. Три формы присутствия:

- **Роль A — «Что видим»:** автоматическая интерпретация графиков и экранов (проактивная подсказка под визуализацией).
- **Роль B — «Что лучше сделать»:** советник, который прогоняет данные через математические модели и даёт обоснованную рекомендацию-решение.
- **Раздел AI-чат:** свободный диалог про свои магазины на естественном языке — с историей, переключением кабинетов, прикреплением графиков и экспортом ответа.

AI — premium-функция (привязка к уровню тарифа, учёт токенов/лимитов).

## 1. Принципы AI (нарушение = смерть доверия)

AI наследует продуктовые принципы (зеркало Ozon, два финконтура, описание у метрики, source-флаг, прогноз=оценка) и добавляет **главное правило**:

> **LLM НЕ считает цифры и модели «в уме».** Все числа и формулы вычисляются **кодом** (детерминированно, воспроизводимо, сходится с кабинетом Ozon). LLM выбирает нужный инструмент, получает готовое число из движка/БД и **только интерпретирует, объясняет и советует**. Любая цифра в ответе — из tool-call, не из генерации. Нет данных → честно «нет данных».

Из этого следует:
- Финансовый ответ всегда указывает контур (официальный отчёт Ozon / наша оперативная модель) и не смешивает их (Принцип 2).
- Прогнозы и рекомендации помечены как **оценка** (Принцип 5); решение — за пользователем.
- AI **не выполняет действий в кабинете Ozon** (не меняет цены/ставки/рекламу). Только советует. Автодействия с подтверждением — фаза 2.
- Каждое число сопровождается источником (Принцип 4).

## 2. Архитектура AI

```
[Фронт: чат + авто-инсайты]
        |
        v
[AI-оркестратор]  --(function calling)-->  [LLM: OpenAI GPT]
        |
        |-- data-tools --> [основной API ozonpro: метрики, P&L, воронка, остатки, цена]
        |-- model-tools -> [расчётные движки: эластичность, юнит-экономика, прогноз,
        |                    оптимизация цены, модель «держать/вывести», ABC, ROMI]
        |
        v
[БД: история чатов, кэш интерпретаций]
```

**Оркестратор** — слой, который принимает запрос (или контекст экрана), даёт LLM набор инструментов, исполняет вызванные инструменты (детерминированно, кодом), собирает результат и возвращает ответ. Сам ничего не «придумывает».

**LLM:** OpenAI GPT с function calling (ключи уже есть). Провайдер абстрагирован (интерфейс `LLMProvider`) — чтобы при желании сменить/добавить модель без переписывания оркестратора.

**Где живёт:** AI-оркестратор — отдельный сервис (репо + Render, см. раздел 8). За данными ходит в основной API `ozonpro` через те же эндпоинты, что и фронт (единый источник правды — Принцип 1).

---

## 3. Роль A — «Что видим» (авто-интерпретация)

Под графиками и на экранах AI сам выдаёт короткую подсказку: что показывает картинка, где аномалия, что важно. Без запроса пользователя.

Примеры:
- Выручка + ДРР: «ДРР растёт с 17.05 при падающей выручке — реклама дорожает, эффективность падает».
- Воронка: «Узкое место — корзина→заказ, на 6 п.п. ниже среднего за период; показы в норме».
- Остатки: «Жираф выходит в стокаут через ~9 дней при текущем темпе продаж».

Механика: лёгкий авто-вызов интерпретации по **данным текущего экрана** (метрики + период + товар), не по картинке. Результат кэшируется (одни и те же данные → один инсайт), чтобы не жечь токены на каждый рендер.

---

## 4. Роль B — «Что лучше сделать» (советник на матмоделях)

Решает операционные дилеммы, взвешивая варианты **с числами** через model-tools:

- **Цена.** «Поднять цену или нет?» → кривая эластичности цена→спрос + юнит-экономика → «при +5% цены прогноз прибыли +X ₽ (эластичность низкая, R² 0.8 — спрос почти не просядет)».
- **Держать или выводить товар.** «Поднять цену и оставить на складе ИЛИ распродать и вывести?» → модель взвешивает маржу, оборачиваемость, заморозку капитала в остатке, стоимость хранения → «оборот 140 дней, маржа 4% — капитал заморожен; выгоднее распродать и вывести, чем держать».
- **Реклама.** «Масштабировать или резать кампанию?» → ДРР / ROMI / CPO по кампании → рекомендация с числом.
- **Закупка.** «Сколько и когда закупить?» → прогноз спроса (сезонность + тренд) + текущий остаток.

Ответ — всегда: рекомендация + числовое обоснование + пометка «оценка» + источник.

## 5. Раздел «AI-чат»

Свободный диалог про свои магазины на естественном языке.

### Функционал
- **Естественный язык:** «Почему упала выручка вчера?», «Какой SKU самый прибыльный за квартал?», «Где я теряю на логистике?».
- **История диалогов:** сессии сохраняются, можно вернуться к прошлому разговору.
- **Переключение между магазинами (кабинетами):** контекст чата привязан к выбранным кабинетам; можно переключать, не теряя историю. Видно, по какому кабинету идёт ответ.
- **Прикрепление графиков в чат:** из любого графика/экрана — кнопка «Обсудить в AI». В чат передаётся **контекст графика (метрики + период + товар), а не картинка** — чтобы AI оперировал точными цифрами (Принцип 1). Произвольные скриншоты-картинки (vision) — опционально, фаза 2, и помечать, что распознавание может ошибаться.
- **Экспорт ответа:**
  - в **отчёт** (PDF/документ) — сохранить разбор AI как файл;
  - в **Telegram** — отправить ответ/сводку себе в Telegram (через бота).

### Поведение чата
- Каждый ответ с цифрами — через инструменты (data/model), не из генерации.
- Если вопрос финансовый — указывает контур (официальный/оперативный).
- Прогноз/совет — помечен «оценка».
- При отсутствии данных — честно сообщает, не выдумывает.

### Данные (БД основного сервиса)
- `ai_chat_sessions(id, user_id, title, cabinet_scope JSONB, created_at, updated_at)`
- `ai_chat_messages(id, session_id, role ENUM('user','assistant','tool'), content, tool_calls JSONB, attachments JSONB, created_at)`
- `attachments` хранит контекст прикреплённого графика (тип, метрики, период, product_id), не растровое изображение.

### Экспорт — детали
- **Отчёт:** ответ AI + использованные данные/график → PDF (через серверную генерацию).
- **Telegram:** интеграция бота. Отправка сообщения — действие; в продукте делается по явному действию пользователя (нажал «Отправить в Telegram»). Токен бота — в env, не во фронте.

## 6. Реестр инструментов (tools)

**data-tools** (выборка фактов — переиспользуют существующие эндпоинты `ozonpro`):
- `get_metrics(cabinet, product, period, metrics[])` — дневные/агрегированные метрики.
- `get_pnl(cabinet, product, period, model)` — P&L (модель: официальная/оперативная).
- `get_funnel(cabinet, product, period)` — воронка и конверсии.
- `get_stock(cabinet, product)` — остатки, дни запаса.
- `get_price(product)` — цена продавца / покупателя / СПП / комиссия.

**model-tools** (детерминированные расчётные движки — обернуть существующие, не дублировать):
- `elasticity(product, factor)` — эластичность + R².
- `unit_economics(product, price?)` — юнит-экономика при заданной цене.
- `demand_forecast(product, horizon)` — прогноз спроса (сезонность+тренд).
- `price_optimizer(product)` — цена, максимизирующая прибыль по кривой.
- `keep_or_drop(product)` — модель «держать/вывести» (вход: маржа, оборачиваемость, остаток, стоимость хранения, заморозка капитала → решение + обоснование).
- `abc_analysis(cabinet)`, `romi(campaign)` — по мере готовности.

Каждый инструмент возвращает значение **+ source + контур (где применимо)**, чтобы LLM мог честно сослаться.

---

## 7. Границы (чего AI не делает)

- Не выдумывает цифры — только из инструментов/БД.
- Не действует в кабинете Ozon (read-only советник). Автодействия — только фаза 2 и только с подтверждением.
- Не смешивает два финансовых контура.
- Не даёт юридических/налоговых гарантий (по налогам — справочно + рекомендация свериться).
- Не отправляет ничего вовне (Telegram, отчёт) без явного действия пользователя.

## 8. Инфраструктура AI (репо + Render + ключи GPT)

> Деплой на Render, ввод ключей и создание аккаунтов выполняет владелец. Автоматизированные ассистенты (включая Claude/Claude Code) **ключи не вводят, аккаунты не создают, Render не настраивают** — только пишут код.

- **Отдельное репо** — для AI-оркестратора (изолировано от основного `ozonpro`). Общается с основным API по HTTP.
- **Render** — хостинг AI-сервиса. Переменные окружения (ключи GPT, токен Telegram-бота, URL основного API, сервисный токен) — в Render Environment, **не в коде и не во фронте**.
- **Ключи GPT (OpenAI):** только на бэкенде AI-сервиса (env). Фронт никогда не видит ключ; фронт ходит в наш AI-эндпоинт, а тот — в OpenAI. Ключ не кладётся в `localStorage`, не передаётся в URL/query.
- **Аутентификация между сервисами:** AI-сервис ходит в основной API с сервисным токеном; данные пользователя — строго по его правам (приватные данные видит только владелец).

### Эндпоинты AI-сервиса (REST)
- `POST /ai/chat` — сообщение в чат (вход: текст, session_id, cabinet_scope, attachments). Возврат: ответ + вызванные инструменты + источники.
- `GET /ai/sessions`, `GET /ai/sessions/{id}` — история.
- `POST /ai/insight` — авто-инсайт по данным экрана (Роль A).
- `POST /ai/export/report` — экспорт ответа в PDF.
- `POST /ai/export/telegram` — отправка в Telegram (по явному действию).

## 9. Фазы

- Раздел **AI-чат**: естественный язык, история, переключение кабинетов, прикрепление графиков (через контекст данных), цифры строго через инструменты.
- Роль B (советник) внутри чата.

**Фаза 2 (заложить, не делать сейчас):**
- Роль A — авто-инсайты «что видим» под графиками.

- Vision по произвольным скриншотам; автодействия в кабинете с подтверждением; AI-анализ отзывов.

## 10. Definition of Done для AI

- Любой числовой ответ воспроизводим и сходится с соответствующим экраном/кабинетом (Принцип 1).
- В ответе виден источник и контур.
- Прогноз/совет помечен «оценка».
- Ключи и токены — только в env AI-сервиса, нигде во фронте/URL/логах.
- Проверено вживую на реальном кабинете (например, «почему упала выручка вчера» по Жирафу — ответ совпадает с тем, что показывает «Объяснение дня»).
