## Север и принципы (фундамент)

**Север.** Худший исход — показать уверенную **неверную** цифру, по которой человек примет решение (закупка, цена, реклама, распродажа). Молча-неверная финматематика опаснее тормозов и дыр.

**Flowoi = «экономист-математик в штате», не ещё один дашборд.**

**3 принципа:**
1. **Зеркало Ozon** — базовые метрики 1:1 с кабинетом. Расхождение = баг.
2. **Два финансовых контура с переключателем:** «Официальные отчёты Ozon» | «Наша модель». **Не смешивать в одной цифре.**
3. **У каждой метрики описание:** что, почему, по каким дням смотреть, факт или оценка.

**Рабочие правила:**
- Маленькими шагами → проверка вживую → дальше. «Готово» = юзер подтвердил на flowoi.ru.
- **Бэкап БД перед каждой миграцией** (`pg_dump` затронутых таблиц).
- **Движок общий по всем кабинетам** — `cabinet_id` всегда параметр, не хардкод.
- **Не угадывай поля** — подтверждай живым вызовом API.
- **Source-флаг на каждое число:** факт API / факт XLSX / оценка. Не смешивать.
- Не переименовывать кодовую базу `ozon-pro`.
- Сначала план → потом код.

## Модель цен (проверена на транзакциях и майском файле Жирафа)

- `seller_working_price` = **19958 ₽** = поле **`marketing_seller_price`** (НЕ `marketing_price`). От неё считается ВСЁ.
- **33000** — мусор, **51999** — зачёркнутая витрина. В финансы не идут.
- `buyer_visible_price` (после СПП) ≈ 13258 (карта) / 12154 (банк) — **маркетинговый слой, маржу продавца НЕ режет** (СПП за счёт Ozon).
- Комиссия FBO ≈ **41%**, считается от **(Выручка + Баллы за скидки)** — подтверждено файлом.
- «СПП = баллы» — **опровергнуто**.
- Региональную цену API не отдаёт (едина по РФ).
- Себестоимость есть не у всех (активный — Бетонорез GlattFix). Без неё прибыль = «не рассчитана / оценка».

## Формула P&L (выверена на Crema Viva, diff = 0)

```
seller_revenue   = Выручка + Баллы за скидки + Программы партнёров
прибыль_до_сс    = seller_revenue − все комиссии/услуги
чистая_прибыль   = прибыль_до_сс − себестоимость × (доставлено − возвращено)
```

- **Баллы за скидки — ПРИТОК, не расход.** Не вычитать.
- По магазину home за май: выручка продавца ≈ **5,84 млн** (не 3,0 млн голой «Выручки»); прибыль до с/с ≈ **1 993 714 ₽**; Crema Viva ≈ **1 141 687 ₽** (контрольный юнит-тест).

## Реалии Ozon API

- `/v1/analytics/data` — троттлинг ~**1 запрос/мин** → весь диапазон **одним вызовом**, `dimension:["sku","day"]`, **не циклом по дням**.
- **Реклама — отдельный Performance API** (другой хост, OAuth, 10 кампаний/отчёт, ~1000 отчётов/сут, отчёт до часа). ДРР только оттуда.
- Bulk-история — Report API (create → poll → download файла).
- `transaction/list` — суммы **на отправление, не на товар** → нужен единый метод разбивки posting→SKU для всех затрат.
- `stock_on_warehouses` даёт `volume` (литры) + остатки по складам (`for_sale/shipped/between_warehouses`) — **только текущие**, историю копим сами.
- **Займов Ozon.Invest в API НЕТ.** «Financing»-операции = услуги (гибкий график −1.5М, досрочная выплата −1.49М), тело/процент не разбиваются.

## Source-флаги (обязательны во всех endpoint'ах)

`sources: dict[str, str]` ∈ `{'api', 'xlsx', 'estimated', 'manual', 'missing'}`

- `'api'` — точные данные API в реальном времени
- `'xlsx'` — из ручного XLSX-отчёта «Общие расходы»
- `'estimated'` — pro-rata / interpolation / weighted-avg
- `'manual'` — введено юзером
- `'missing'` — нет данных, показывать «—», не 0

**Не записывать оценку в primary колонку без флага.** Оценка → отдельная таблица + UI «≈ оценка».
